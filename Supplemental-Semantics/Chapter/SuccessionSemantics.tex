\ksec{Successions (KerML 8.4.4.6.3)}

\pn Successions\index{succession} are binary connectors requiring their source and target features to identify occurrences that are ordered
in time.  Successions are typed by the association \texttt{Occurrences::HappensBefore} with the source feature being the earlier occurrence and the target feature being the later occurrence.
\comment{Why not HappensJustBefore?}

\ecaption{succession}
\begin{lstlisting}
succession first f1 then f2;
\end{lstlisting}
is equivalent to:
\ecaption{succession equivalent}
\begin{lstlisting}
connector subsets Occurrences::happensBeforeLinks {
  end feature earlierOccurrence references f1
    redefines Occurrences::HappensBefore::earlierOccurrence;
  end feature laterOccurrence references f2
    redefines Occurrences::HappensBefore::laterOccurrence;
}
\end{lstlisting}


\pn The semantics of \texttt{succession} can be easily be defined using the \texttt{precedes} Allen's intervals operator (section \ref{sec:allen}).


\begin{restatable}{definition}{succession}~\blTitle{df-succession}~   Define Succession
\begin{align}
\texttt{succession}~\texttt{first}~f_1~\texttt{then}~f_2\texttt{;}~\Rightarrow~ % \notag \\
\vdash \texttt{precedes}(f_1,f_2)~\label{eq:df-succession}\tag{df-succession}
\end{align}
\end{restatable}

\pn \texttt{df-succession} is book-original, with no \texttt{SFS.mm} formalization of its own
(confirmed absent from \texttt{SFS.mm} by grep) -- \texttt{succession} is KerML's own concrete
syntax, not a domain predicate ported from a real \texttt{.kerml} file's \texttt{@Assert}, so there
is nothing to port \emph{from}. It does have real Lean backing below.

\begin{restatable}{leandefinition}{successionLean}~\leanTitle{Succession}~ Define succession in Lean,
directly as \texttt{precedes} -- book-original, not ported from a real \texttt{.kerml} file's
\texttt{@Assert} like every other \texttt{df-}/\texttt{ax-} in \texttt{SFS.lean}, since
\texttt{succession} is KerML's own concrete syntax (a connector subsetting
\texttt{Occurrences::happensBeforeLinks}), not a domain predicate a modeler writes into a
\texttt{.kerml} file.

\texttt{\textcolor{leancolor}{def} \textcolor{leanyellow}{Succession} (f1 f2 : Occurrence) : Prop := precedes f1 f2}
\label{Succession}
\end{restatable}

\begin{restatable}{leantheorem}{dfSuccessionLean}~\leanTitle{df\_succession}~ The book's own
\ref{eq:df-succession} biconditional, in Lean -- free directly from \texttt{Succession}'s own
definition.

\texttt{\textcolor{leancolor}{theorem} \textcolor{leanyellow}{df\_succession} (f1 f2 : Occurrence) :}

\texttt{~~Succession f1 f2 $\leftrightarrow$ precedes f1 f2 := Iff.rfl}
\label{df_succession}
\end{restatable}
